> 版本：方案稿（未开发）

## 一、先说结论：现在为什么"普通"

当前记账模块是**功能正确的流水账工具**：能记、能改、能删、能看汇总。
但它只回答了"我花了多少"，没有回答三个更关键的问题：

1. **我现在还能花多少？**（决策）
2. **我今天记这一笔，有什么反馈？**（即时回报）
3. **这个月我过得怎么样？**（复盘与成就感）

手机端还有第四个问题，是桌面端根本不存在的：

4. **我要记一笔，需要先打开 App、找到 Tab、再点按钮吗？**

竞品在手机端把这件事拆成了三层入口：桌面小组件 → 长按图标/控制中心 → 打开即记账。
小财通现在只有最后一层，而且打开后还要点"记一笔"。

### 用户为什么弃用（手机端真实评论）

| 弃用原因 | 证据 | 启示 |
|---|---|---|
| 输入太麻烦、太耗时 | App Store 评论："没办法坚持就是因为输入很麻烦，很耗费时间" | 打开即记、默认值、3 步内完成 |
| 每次切后台回来要重新进页面 | 评论把"切屏不重进"当成最大优点 | 保持页面状态，不因切后台重置 |
| 只复盘过去，不指导现在 | 行业分析：追踪型 App 只说"花超了" | 首页给"今天还能花" |
| 负反馈制造羞耻 | 红色超支警告导致回避打开 | 超支给调剂方案，不给指责 |
| 数据带不走 | 停更/换机/导出收费的公开案例 | 本地存储 + 免费导出 |
| 广告与收费陷阱 | 基础功能收费、打卡返现被集中投诉 | 无广告、不收费、不返现 |

## 三、小财通的差异化

市面上记账 App 要么纯记账，要么纯投资，要么靠账号和云。
小财通已经有：**本地 SQLite + 基金持仓 + 市场事件 + 盯盘提醒**，无账号、无广告、无云。

所以定位不是"又一个记账 App"，而是：

> **唯一一个把「今天花多少」和「钱攒成什么」放在同一块手机屏幕的本地理财账本。**

一句话：**记账管今天，持仓管明天。**

由此长出的独有亮点：
- 总资产 = 现金账户 + 基金市值（一个数字看全貌）
- 月结余 → 一键存入储蓄/加仓
- 消费体检 + 组合体检，同一套产品语言

## 四、手机端专属：把"打开成本"降到零

这是本次核对后新增的重点。桌面端方案只会优化"打开之后"，手机端必须优化"打开之前"。

### 4.1 四层入口（按成本从低到高）

| 层级 | 做法 | 小财通可行性 | 成本 | 优先级 |
|---|---|---|---|---|
| ① 长按图标快捷方式 | 长按桌面图标弹出「记一笔 / 看今天 / 看预算」，直达对应页 | Android `shortcuts.xml` 静态快捷方式 + Intent extra，前端识别后直接进记账 | 低（原生清单 + 前端路由） | **P0** |
| ② 打开即记账 | 设置项"快速记账"：打开 App 直接落在金额键盘，而不是首页 | 前端一个状态位，无需原生 | 极低 | **P0** |
| ③ 桌面小组件 | 2×2 小尺寸：今日支出 + "记一笔"按钮；点分类直达记账 | 需 `AppWidgetProvider` + `RemoteViews`，Capacitor 需自写原生模块 | 中（约半天到一天） | **P1** |
| ④ 通知/锁屏 | 每日 21:00 "今天还有 ¥X，记一下今天的账"；点通知进记账 | 已有本地通知能力（`@capacitor/local-notifications`） | 低 | **P1** |

不建议做：
- **悬浮球**：需要悬浮窗权限，用户抵触、审核麻烦，且与"无广告、干净"的定位冲突。
- **控制中心磁贴**：Android 可用但入口太深，收益小于小组件。
- **自动记账（监听通知/无障碍）**：权限敏感、机型差异大、容易误记，当前不做。

### 4.2 小组件具体形态（只做 2 个，不做 14 个）

| 小组件 | 尺寸 | 显示 | 点击 |
|---|---|---|---|
| 今日速览 | 2×2 | 今日支出、今天还能花、一个"＋"按钮 | "+"直达记一笔；卡片进记账页 |
| 预算进度 | 4×2 | 本月已用/预算 + 进度条 + 剩余天数 | 进预算页 |

理由：蜜蜂记账做了 14 种规格，但小财通不需要"全"，需要"每天都看一眼的那个数字"。

### 4.3 手机端必须做对的细节

| 细节 | 具体要求 |
|---|---|
| 单手可达 | 主按钮和金额键盘落在屏幕下半部；"记一笔"不做在顶部 |
| 键盘 | 数字键盘优先，带 `+ - × ÷`；不弹系统全键盘 |
| 默认值 | 账户=上次使用；时间=现在；类型=支出；分类=最近 30 天高频第一个 |
| 页面状态 | 切后台再回来不重置页面、不丢已输入金额 |
| 震动 | 保存成功一次轻震动；超支不震动（避免负面强化） |
| 通知 | 一天最多 1 条；断签不指责，文案是"补一下昨天的就行" |
| 分享 | 月报生成为图片存本地相册，不走网络 |
| 隐私 | 金额一键隐身；支持 4 位 PIN；切后台自动模糊预览 |

## 六、记账页信息架构（r4.7）

现在：月份 → 汇总 → 记一笔 → 5 页签（流水/统计/预算/账户/分类）

建议：

```
月份 + 眼睛（隐身）
┌ 今天还能花  ¥122.50  ┐
│ 本月剩 ¥1,470 / ¥1,500 │  进度环
└──────────────────────┘
[ 常用分类 6 个图标，点一下直接记 ]
[ ＋ 记一笔（完整模式） ]
页签：流水 · 日历 · 预算 · 资产 · 更多
```

理由：
- "今天还能花"必须在第一屏，这是决策数字
- 常用分类前置，把记账从"打开弹窗填表"变成"点一下"
- "统计"并入"日历"页下方（分类占比 + 每日），少一个页签
- "分类管理"收进"更多"，日常不需要看

## 七、明确不做（避免走偏）

| 不做 | 原因 |
|---|---|
| 打卡返现、补签付费、连续签到奖现金 | 已被 36 氪与黑猫投诉集中曝光，伤害用户 |
| 公开排行榜、余额攀比 | 比的是收入，会打击大多数人 |
| 开屏广告、基础记账收费 | 用户最敏感的两件事 |
| 悬浮球、控制中心磁贴 | 权限重、入口深，收益低 |
| 监听通知/无障碍的自动记账 | 权限敏感、误记风险高 |
| 云同步 / 账号体系 | 与"本地、无账号"定位冲突；用导出备份解决 |
| AI 自动记账 / 截图 OCR | 需要模型与网络，当前架构不满足 |
| 复式记账、多币种、多账本 | 学习成本高，偏离学生日常 |
