# 小财通 — 产品规划

> 本文件是产品级规划文档，随产品细化持续更新。与项目根目录 [CLAUDE.md](../CLAUDE.md)（协作规则+需求摘要+决策记录）互相引用。
> 创建日期：2026-08-29（迁移自 Claude Code 计划文件）

## 1. 背景

用户是零编程基础的基金投资者，首次使用 Claude Code，想从零开发桌面端基金管理工具「小财通」。产品处于想法阶段，按"先完善需求、后开发"的节奏推进：**当前不写代码**，逐模块细化产品，每阶段经用户确认后再进入下一阶段。

## 2. 产品定位

- 一句话：**把基金投资者散落在各处的信息（持仓、行情、消息、经理动态）聚合到一个中立、易懂、会主动提醒的入口。**
- 解决的核心痛点：
  1. 信息分散——持仓在支付宝，行情开 App，新闻刷公众号，经理离任没人告诉
  2. 盯盘费神——手动刷行情耗时且易漏关键变化
  3. 看不懂专业指标——回撤、夏普比率、规模变化等术语难理解
  4. 噪音太多——小道消息、营销软文、标题党混杂
  5. 平台有销售导向——支付宝/天天基金本质是卖基金的，小财通不卖基金所以立场中立

## 3. 关键风险（必须直面的问题）

1. **数据源是生死线（最重要）**：支付宝/天天基金不向个人开发者开放接口；免费方案（如 AKShare）数据来自爬取，非官方、可能失效，必须有降级预案。这是产品可行性的第一前提，先做调研。
2. **"基金涨跌幅盘中提醒"有现实限制**：监管要求下盘中估值已下线，场外基金净值每天收盘后（晚上）才更新一次。场外基金提醒只能是收盘后检查；盘中提醒只对指数/ETF/黄金/美股有效。需管理用户预期。
3. **新闻智能筛选没法一步到位**：完全自动识别小道消息需要 AI，初期做"白名单媒体+规则过滤"的简单可靠版本，逐步加 AI。
4. **合规红线**："分析"与"建议"的措辞边界要持续注意——可以说"这只基金回撤很大"，避免说"建议买入/卖出"。按"将来可能公开发布"的标准写文案。
5. **全球市场 vs 国内可访问的矛盾**：美股实时免费数据、SEC 公告站在国内可能访问不稳定。方案：国内可访问的行情源为主，官方公告类在用代理时优先官方、无代理时用可靠降级渠道，功能始终可用。
6. **单机 App 的提醒能力有限**：桌面通知只在 App 运行时有效，电脑关机收不到。手机推送需服务器，留到产品跑起来后评估。

## 5. 核心设计原则

**零成本完成可用版本优先，但不得为自用把架构写死**——所有涉及数据源、提醒、软件架构的设计都必须考虑未来公开发布时可以平滑升级：

- 数据源做接口抽象层：换源/加源/接付费源只改适配器，不动业务代码
- 提醒做通道抽象层：当前只实现桌面通知，预留邮件、手机推送扩展位
- 数据存储本地为主，为将来账号系统/云同步预留边界（用户数据与程序逻辑分离）
- 合规措辞从第一天按"将来可能公开发布"的标准写

## 6. 产品细化路线图

1. **逐模块细化需求**（当前阶段）：我的基金 → 盯盘提醒 → 基金分析 → 消息筛选 → 经理跟踪 → 发现/赛道 → 界面
2. **数据源调研**：整理免费方案对比（覆盖范围、稳定性、降级预案），由用户拍板

5. **MVP 开发**：我的基金 + 首页概览 + 条件提醒 + 主要指数行情
6. 之后按 P1 → P2 → P3 迭代

## 9. 我的基金模块需求（已确认 2026-08-29）

> 本模块为 P0 优先级。以下内容于 2026-08-29 讨论确认（确认时未写代码），与 CLAUDE.md 决策记录保持一致。

### 9.1 模块解决的问题

一句话：**你买了哪些基金、现在值多少钱、赚了还是亏了、今天有什么变化，在一个地方就能看清。**

| 痛点 | 现状 |
|---|---|
| 钱分散多处 | 持仓在支付宝、天天基金等多个平台，算总账要开好几个 App |
| 算不清盈亏 | 每笔买入价格不同、有分红再投，自己心算易错，平台收益口径不统一 |
| 天天盯净值 | 场外基金净值晚上才更新，懒得每天逐个打开 |
| 想先观察再买 | 有些基金没买但想先关注行情 |

### 9.2 用户完整使用流程

```
首次使用：添加基金 → 填持有信息（本金、份额）→ 完成
日常使用：打开 → 一眼看到总资产和今日盈亏 → 点开单只看详情 → 数据自动更新
有变动时：买入 → 补记一笔；卖出 → 更新；清仓 → 自动移入历史持仓
```

### 9.3 第一版功能清单

**核心功能：**
1. 添加基金：输代码或搜名字，自动识别基金基本信息（名称、类型、基金经理等）
2. 持仓管理：添加、修改、删除持有记录（本金、份额、备注）
3. 收益计算：自动拉取每日净值，算出当前市值、收益金额、收益率、今日涨跌
4. 持仓总览：总资产、总收益 + 每只基金一行（净值、涨跌、收益）
5. 基金详情页：单只基金看净值走势、收益明细
6. 关注列表：没买的基金也能加，只看行情不记盈亏
7. 数据备份：本地数据可导出/导入，防止重装丢失

**第一版暂不做：** 总资产历史走势图（归首页概览模块）、申购赎回手续费精细计算、与盯盘提醒联动（下一个模块）。

### 9.4 数据字段与收益口径（简单模式）

每只持仓记录：基金（代码/名称/基本信息）、本金（总投入）、份额、状态（持仓/关注/历史持仓）、添加日期、备注。

- 当前市值 = 最新净值 × 份额
- 收益金额 = 市值 − 本金；收益率 = 收益 ÷ 本金
- 今日收益 = 份额 ×（今日净值 − 昨日净值）
- 部分卖出时：提供"本金按比例减少"的辅助计算，用户可手动修正
- 净值数据源、存储格式等技术细节留到"数据源调研 / 技术栈选型"阶段

### 9.5 本模块已确认决策

| 决策项 | 结论 | 理由 |
|---|---|---|
| 记录方式 | 简单模式起步（本金+份额），预留升级 | 录入最省事；底层预留升级到完整流水，日后升级不用重新录入 |
| 资产范围 | 第一版只场外基金 | 贴合当前需求，录入简单；场内 ETF/股票后续再评估 |
| 清仓处理 | 保留为历史持仓 | 可随时查看该基金累计赚/亏，也可手动删除 |
| 数据更新 | 打开时自动更新 + 手动刷新 | 实现简单可靠，适合第一版 |

## 10. 盯盘提醒模块需求（已确认 2026-08-29）

> 本模块为 P0 优先级。以下内容于 2026-08-29 讨论确认（确认时未写代码），与 CLAUDE.md、docs/决策记录.md 保持一致。

### 10.1 模块解决的问题

一句话：**不用自己天天盯盘，把关心的东西和条件设好，达到条件时软件主动桌面弹窗告诉你。**

两类提醒对象更新节奏不同（关键约束）：

| 类别 | 举例 | 数据何时更新 | 何时检查提醒 |
|---|---|---|---|
| 指数/赛道/黄金 | 沪深300、恒生科技、标普500、纳斯达克100、黄金、人工智能、半导体、创新药、生物科技等 | 交易时间实时变化 | 交易时段内每 5 分钟 |
| 场外基金 | 我的基金持仓 | 每天收盘后更新净值（盘中估值已按监管要求下线） | 每日收盘后检查一次 |

痛点：盯盘费神、易漏关键变化；关注对象多、逐个打开看累；条件达标无人通知（如基金跌超 5%、沪深300 涨破 4000 点）。

### 10.2 用户完整使用流程

```
首次：添加提醒 → 选对象（指数/赛道/我的基金）→ 设条件 → 完成
日常：软件后台检查 → 条件达标 → 桌面弹窗 → 点开查看或忽略
管理：提醒列表里暂停/恢复/删除，查看历史触发记录
```

### 10.3 第一版功能清单

**核心功能：**
1. 提醒对象：预设常见指数/赛道清单（沪深300、恒生科技、标普500、纳斯达克100、黄金、人工智能、半导体、创新药、生物科技等，清单可随时调整）+ 从「我的基金」持仓/关注列表选基金
2. 提醒条件（两种类型）：
   - 涨跌幅：比昨日收盘涨/跌超过 X%（如"沪深300 单日涨超 2%"）
   - 数值线：涨破/跌破某点位（如"沪深300 涨破 4000 点"）
3. 触发检查：指数交易时段内每 5 分钟检查一次；场外基金每日收盘后检查一次
4. 桌面通知：弹窗提醒
5. 提醒管理：列表查看、暂停、恢复、删除
6. 防骚扰：同一提醒达标后当天不再重复弹
7. 历史提醒记录：可查"最近提醒过什么"

**第一版暂不做：** 邮件/手机推送（通道已预留）、开盘简报、多条件组合（如"涨超 5% 且成交放大"）。

### 10.4 本模块已确认决策

| 决策项 | 结论 | 理由 |
|---|---|---|
| 提醒对象 | 预设清单 + 我的基金 | 符合现有需求，第一版简单可靠；任意代码搜索成本高，后续再评估 |
| 条件类型 | 涨跌幅 + 数值线 | 数值线对指数更直观；只做涨跌幅则"涨破 4000 点"设不了 |
| 基金提醒内容 | 净值涨跌 + 我的收益 | 收益类提醒用持仓数据算，更贴近用户自己的钱 |
| 盘中检查频率 | 每 5 分钟 | 一天约 50 次请求，免费数据源通常扛得住，也不会错过太多 |

### 10.5 模块间依赖与待细化

### 10.6 补充需求：提前设置未来条件提醒（已确认 2026-08-29）

用户需求场景：今晚设置"明天跌幅达 3% 就提醒我，按自己的计划考虑卖出"——软件只负责监控与提醒，**不自动买卖、不替用户作决定、不解读用户备注**。

**需求要点（已确认）：**
1. 提醒对象：基金、指数、赛道（同现有）
2. 条件类型（同现有）：当日跌幅达 X% / 当日涨幅达 X% / 跌破净值或指数点位 / 涨破净值或指数点位
3. **有效期方案（已确认）**：底层统一按"组合模式"设计（每条提醒 = 开始日期 + 结束日期，结束留空 = 持续到触发）；**界面只提供 3 个快捷选项**，普通用户无需理解底层：
   - **仅下一交易日**：系统自动计算下一个实际交易日（如周五设置 → 下周一生效），用户不填日期；当天检查结束后自动失效
   - **持续到触发**：从今天（或用户选的开始日期）起一直监控，触发一次后自动失效
   - **自定义时间范围**：用户填开始和结束日期，范围内每天检查，到期自动失效
4. 触发后：桌面通知 + 历史记录留痕（同现有）
5. **用户备注**（已确认）：用户可自填备注（如"达到止损条件，检查是否按原计划卖出"）
6. 备注仅用户自己可见；小财通**不解读备注内容、不把它作为投资建议展示**（备注旁不出现任何软件观点）
7. 检查节奏遵循既有规则：场外基金收盘后按净值检查（盘中无实时估值）；指数/赛道盘中实时检查

## 12. 重要消息收集模块需求（已确认 2026-08-29）

> 本模块为 P1 优先级。以下内容于 2026-08-29 讨论确认（确认时未写代码），与 CLAUDE.md、docs/决策记录.md 保持一致。

### 12.1 模块解决的问题

一句话：**和你有关的重要财经消息，自动帮你收集、筛选、翻译成大白话，只留下值得看的；同时帮你发现值得关注的新方向。**

| 痛点 | 现状 |
|---|---|
| 信息分散 | 消息散落在公众号、新闻 App、论坛里，没人聚合 |
| 噪音太多 | 小道消息、营销软文、标题党、重复新闻混杂，重要的被淹没 |
| 看不懂、不知与自己何关 | 一条公告出来，不知道"关我什么事" |
| 错过关键变化 | 经理离任、重仓股暴雷、政策出台，等发现往往晚了 |
| 视野局限 | 只看自己关注的，其他赛道/公司的重大变化无从知晓 |

### 12.2 消息区域结构（两区域 + 特殊类型）

**区域一：我的关注**（主消息列表）
- 展示：用户持有或主动关注的**基金、赛道、基金经理、指数及相关公司**的重要消息
- 通知：**独立开关**，与市场发现互不影响

**区域二：市场发现**（单独界面）
- 展示：用户**目前没有关注**、但经筛选后具有**较高研究价值**的重要消息，帮助用户发现新的值得关注方向
- 内容举例：其他赛道的重要变化、龙头公司财报、重大政策、重大技术突破、有研究价值公司的重要变化
- 通知：**默认只在 APP 内展示，不推送**；用户开启通知后，只推送"重要程度较高"的消息（规则打分，见 12.4）
- 每日展示量：**每天最多 20 条**，按重要性从高到低取前 20（第一版，后续可调）

**特殊消息类型：重大市场事件**
- 全市场影响较大的事件（如重大宏观政策、美联储决议等）
- 通知**默认开启**，用户可随时关闭（默认值已于 2026-08-30 修订为"桌面通知一律默认关、首次开启询问"，详见 12.7）
- 展示位置：**两个区域都显示**——与用户关注相关的在"我的关注"，其余在"市场发现"；通知由**一个独立开关**统一控制，不会重复推送

### 12.3 收集范围

| 类型 | 举例 |
|---|---|
| 财报与公告 | 重仓公司财报、重大公告、龙头公司变化 |
| 基金动态 | 基金重仓股变化、基金经理离任/增聘 |
| 政策与宏观 | 行业政策、宏观数据、并购、技术进展 |
| 医药特殊项 | 临床结果、药物审批、FDA 等监管信息 |
| 重大市场事件 | 全市场影响较大的事件（重大宏观政策、美联储决议等） |

**每条消息说明**：发生了什么、来源、时间、为什么值得关注、影响哪些公司/赛道/基金、影响方向（正面/负面/暂无法判断）、重要性评分。

### 12.4 第一版功能清单

**核心功能：**
1. 白名单来源：预置可信来源（交易所/证监会/基金公司公告渠道、权威财经媒体）+ 用户可自定义添加/屏蔽
2. 自动抓取 + 分类：每天定时抓取，按类型归类（财报/公告/政策/宏观/经理变动/临床审批/重大市场事件…）
3. 规则过滤：
   - 硬过滤：标题党、营销词（"必涨""翻倍"）、重复新闻自动去重（保留首发来源，标注"另有 N 家报道"）
   - 相关性过滤：与持仓重仓股、关注赛道相关的进"我的关注"，其余有研究价值的进"市场发现"
4. **重要性打分**：按消息类型权重 + 影响范围（影响多少公司/赛道）+ 来源权威度综合打分；决定市场发现推送门槛（APP 内展示线更宽松）和每日 20 条排序
5. 白话摘要：模板提取"谁、什么时候、什么事"，生成一句话摘要
6. 影响标注：标记影响基金/赛道/公司 + 影响方向（规则关键词判断，拿不准标"待观察"）
7. 消息列表 + 详情：我的关注/市场发现各自列表，时间倒序，点开看完整说明
8. 已读 / 收藏 / 忽略：忽略的以后少推
9. 通知设置：我的关注、市场发现、重大市场事件三个独立开关

**第一版暂不做：** AI 智能筛选与摘要（预留 AI 升级位）、全文语义分类。

## 14. 赛道分析 / 基金发现模块需求（已确认 2026-08-29）

> 本模块为 P2 优先级（含两个子模块：赛道分析、基金/赛道发现）。以下内容于 2026-08-29 讨论确认（确认时未写代码），与 CLAUDE.md、docs/决策记录.md 保持一致。

### 14.1 模块解决的问题

一句话：**看清一个行业（赛道）现在贵不贵、涨到哪了、有什么风险，并发现值得研究的新方向——但绝不替用户下"买"的结论。**

| 痛点 | 现状 |
|---|---|
| 不知道赛道贵不贵 | 看到"半导体大涨"的新闻，不知道还能不能研究 |
| 想了解一个行业 | 趋势、估值、资金、政策、龙头公司、风险——散落各处 |

## 16. 趋势与风险分析模块需求（已确认 2026-08-29）

### 16.1 模块解决的问题

一句话：**判断一个赛道/基金现在是什么状态（强还是弱、风险高还是低、贵还是便宜），帮用户想清楚"现在该不该研究它"——但绝不预测明天涨跌。**

| 痛点 | 现状 |
|---|---|
| 不知道强还是弱 | 面对一个赛道或基金，不知道现在是什么状态、风险大不大 |
| 没有客观依据 | "该不该关注"全靠感觉或新闻标题 |
| 情景分析不会算 | 想理解"如果发生 X 会怎样"，自己算不来 |

**合规红线**：不做"明天涨跌"预测，只做趋势、风险、估值位置、资金变化、情景分析，作为研究辅助。

### 16.2 与已有模块的关系

| 模块 | 定位 |

共用数据（趋势、估值、资金），P3 增加：强弱判断、风险评级、情景分析。

### 16.3 第一版功能清单

**分析对象：预设赛道 + 我的基金（持仓/关注）**

**核心功能：**

2. 风险评级：高/中/低 + 理由（综合波动大小、最大回撤、估值位置），透明可解释
3. 估值位置：贵/合理/便宜（复用赛道分析的估值百分位）
4. ~~资金变化~~：**第一版不做**（北向资金 2024-08 起断供，数据源调研确认，见第 17 节；后续数据源稳定后再考虑加回）
5. 情景分析：预置常见情景（如"大盘跌 10%""利率上升"），说明对持仓/赛道的影响方向和程度——**只做说明，不做预测**

## 17. 数据源调研结论（已确认 2026-08-29）

> 调研目标：每类数据找免费、稳定、可降级的来源，由用户 2026-08-29 拍板确认。所有数据源通过**接口抽象层**接入（换源/加源/接付费源只改适配器，不动业务代码）。

### 17.1 总体方案

- **取数方式**：AKShare 开源库为主 + 腾讯财经直连接口补充
  - AKShare：免费开源、免注册，覆盖基金净值/基本信息/经理数据/估值历史/新闻等，开发最快
  - 腾讯直连：补充指数/ETF/黄金/海外盘中实时行情
  - 不使用 Tushare（需实名注册+积分限频，与 AKShare 覆盖重叠）
- **行情多源切换**：腾讯 → 新浪 → 东财 三源自动切换（免费源都可能挂，自动换源容灾）

### 17.2 各类数据源选型

| 数据类别 | 主源 | 备用源 | 降级方案 |
|---|---|---|---|
| 基金净值/基本信息 | 天天基金直连接口 + AKShare | AKShare（聚合多源） | 两路都失败时提示"数据暂不可用，稍后重试" |
| 基金历史净值/经理数据 | AKShare | efinance 开源库 | 同上 |
| A股/指数/黄金行情 | 腾讯财经（盘中实时） | 新浪 → 东财 自动切换 | 三源都挂时保留上次数据并标注时间 |
| 海外行情（美股/港股） | 腾讯财经 | 新浪 | Yahoo 国内受限不可用，不采用 |
| 指数估值（PE/PB 历史） | 中证指数官网（官方） | 乐咕乐股 | 官网不可用时切备用 |
| 公告/新闻 | 巨潮资讯官方接口（公告）+ 官方白名单 RSS | 东财新闻接口 | 公告源权威优先；新闻降级为 RSS |
| 资金面 | **第一版不做** | — | — |

### 17.3 重要调研发现（影响需求的）

1. **北向资金断供**：2024-08 起监管不再实时披露北向资金明细 → 资金面第一版不做（赛道分析、趋势与风险分析两处已同步调整）
2. **东财接口限流严格**：串行请求 ≥1 秒间隔、QPS≤2、有 IP 封禁案例 → 开发时控制请求频率（盯盘每 5 分钟检查远低于限流线）
3. **跨境数据有延迟**：免费源跨境行情延迟 30 秒~数分钟；腾讯/新浪秒级，适合盘中提醒；AKShare 跨境延迟大，不适合实时
4. **Yahoo 国内不可用**：海外行情以腾讯为主、新浪备

## 18. 技术栈选型结论（已确认 2026-08-29）

> 用户 2026-08-29 拍板：**pywebview（Python 数据层 + 网页界面）+ SQLite 本地数据库**。写代码前的最后一个大决定已定，下一步进入界面原型。

### 18.1 技术栈总览（大白话）

- **数据层**：Python —— AKShare 免费数据库只能用 Python 调用，这是最省钱的路线
- **界面层**：网页技术（HTML/CSS/JS）嵌入原生窗口（pywebview）—— 界面想怎么设计就怎么设计，开发最快最好看
- **存储**：SQLite 小数据库 —— 查询快、防崩溃、将来云同步方便

### 18.2 为什么这么选

| 考虑点 | 结论 |
|---|---|
| 数据源兼容 | AKShare 是 Python 库，数据层用 Python 是唯一省钱路线 |
| 界面要求 | "简洁现代"是首页概览的核心要求，网页技术做界面最灵活 |
| 开发速度 | Claude Code 写网页界面最快，写原生界面（Qt）最慢 |
| 体积/复杂度 | pywebview 居中（100~200MB），比 Electron（200MB+ 且双程序）轻 |
| 将来升级 | pywebview 界面本质是网页，将来要 web 化或换壳可平滑迁移 |

### 18.3 架构草图（文字版）

```
┌─────────────────────────────────┐
│  网页界面（HTML/CSS/JS）           │  ← 用户看到的窗口
├─────────────────────────────────┤
│  pywebview 桥（Python↔网页）       │  ← 界面与数据之间的通道
├─────────────────────────────────┤
│  Python 数据层                    │  ← 调 AKShare/腾讯直连等拿数据、算收益
│  - 数据源接口抽象层（主源+备用+降级）   │
│  - 提醒引擎（每 5 分钟检查）          │
├─────────────────────────────────┤
│  SQLite 本地数据库                 │  ← 存持仓、提醒、消息、设置
└─────────────────────────────────┘
```

## 19. 外观设置（深色模式）需求（已确认 2026-08-29）

> 功能需求 2026-08-29 提出并确认（5 种模式、天文算法、城市列表、降级方案）。
> ✅ **外观配色方案已于 2026-08-29 确认采用**（浅色=柔和暖白，深色=柔和墨灰；主题颜色由用户自选），正式 UI 决策见下方 19.5。
> **深色模式不是简单把背景涂黑**，整套配色重新设计（背景、卡片、文字、边框、涨跌颜色、标签、图表），保证夜间舒服且清晰。浅色模式保留现有设计风格。

### 19.1 功能需求

- 入口：**设置 → 外观**
- **5 种外观模式**：
  1. **跟随日出日落**：根据用户所在城市计算当天日出/日落时间，日落后自动进入深色，日出后恢复浅色
  2. **跟随系统**：跟随 Windows / Mac 当前的深色/浅色设置
  3. **自定义时间**：用户自己设置几点进入深色、几点恢复浅色
  4. **始终浅色**（默认）
  5. **始终深色**

### 19.2 实现决策（已确认）

| 决策项 | 结论 | 理由 |
|---|---|---|
| 日出日落来源 | 内置天文算法 | 纯本地计算、免费、不需要网络、永远可用、精确 |
| 城市位置 | 内置城市列表（几百个中国主要城市含经纬度，下拉选择） | 不用联网、不涉及隐私、永久可用；不要求持续精确定位 |
| 降级方案 | 未设置城市 → 按北京时间（东八区）切换，设置中提示"未设置城市，按北京时间切换" | 简单可靠 |

### 19.3 深色配色设计原则

- 背景用**深蓝灰**（非纯黑，避免刺眼对比）；卡片比背景亮一档形成层次
- 文字用**柔和浅灰**，保证夜间清晰；分割线用暗色
- 涨/跌颜色**提亮**（深色下原色会发暗发灰）
- 标签用"深底亮字"保证可读
- 图表颜色同步设计（图表模块开发时执行）
- 切换时有平滑过渡动画

## 22. 开机自动启动与后台运行（已确认 2026-08-30）

> 用户 2026-08-30 提出并确认。解决"桌面通知与盯盘提醒只有软件运行时才工作，用户却不想一直开着主窗口"的产品逻辑缺口。Windows 与 Mac 最终都要支持；具体技术实现（开机启动项、托盘/菜单栏、后台调度机制）留到 MVP 开发阶段由用户选型。

### 22.1 需求要点（用户最终决定）

1. **登录时自动启动开关**（设置页提供，默认关）：开启后登录电脑即自动启动，**默认在后台运行（托盘/菜单栏图标），不弹出主窗口**。
2. **关闭主窗口行为**（设置页二选一，默认"退出小财通"）：
   - 最小化到后台继续运行
   - 退出小财通
   - 当存在生效中的盯盘提醒或已开启的后台通知任务时，用户**第一次**关闭主窗口需明确提示："退出小财通后，实时提醒将停止。"由用户选择"最小化到后台"或"退出小财通"，并可勾选"记住我的选择"（之后在设置中可改）。
3. **首次询问开机自启（各场景至多一次，拒绝后不反复询问）**：
   - 首次创建盯盘提醒时询问："为了不错过提醒，是否允许小财通登录电脑后自动启动？"
   - 首次开启桌面通知时询问（同上）
   - 用户拒绝后仍可正常使用，并明确告知："小财通未运行期间无法发送实时桌面提醒。"设置页可随时修改。
4. **托盘/菜单栏图标**（后台运行时常驻）：可打开主界面、暂停全部提醒、退出小财通；**第一次进入后台时提示一次**（如"小财通仍在后台运行，点击托盘图标可打开或退出"）；存在生效中的提醒时点击"退出"需再次明确提示"退出后提醒将停止"。
5. **后台任务范围（轻量）**：后台只运行用户明确开启的后台任务——① 生效中的盯盘提醒监控（按第 10 节节奏检查）；② 已开启桌面通知的消息监控。首页行情、分析、发现等不需要后台工作的内容，在用户打开主界面后再刷新，避免无意义占用资源；没有需要监控的任务时尽量休眠。
6. **关机/睡眠/休眠恢复补偿**：电脑关机、睡眠或休眠期间无法保证实时监控；系统恢复后进行一次补偿检查，并区分"实时触发"与"恢复后发现已触发"，避免大量过期通知一次性弹出。
7. **单实例运行**：软件只允许一个实例；重复启动时唤醒已有实例并显示主窗口。
8. **托盘状态提示**：后台提醒服务异常（如数据源全部失败）时托盘图标显示警示状态，避免静默失败。

### 22.2 本模块已确认决策

| 决策项 | 结论 | 理由 |
|---|---|---|
| 开关结构（A 组，A1 优化版） | 「登录时自动启动」开关 + 「关闭主窗口行为」二选一（最小化到后台 / 退出小财通）；有生效任务时首次关闭提示并可记住选择 | 各自单一用途、小白能懂；联动提示防止"误关窗口丢提醒" |
| 首次询问时机（B 组，B1） | 首次创建盯盘提醒、首次开启桌面通知各问一次；拒绝后不反复；设置随时改 | 两条路径各自贴切；不打扰、不纠缠 |
| 托盘交互（C 组，C1） | 图标常驻：打开主界面 / 暂停全部提醒 / 退出；首次进入后台提示一次；有生效提醒时退出二次确认 | 用户随时能找回、能彻底退出，后台驻留的基本礼貌 |
| 后台任务范围 | 只运行用户开启的后台任务（生效提醒 + 已开启通知的消息监控）；其他内容打开主界面再刷新 | 轻量、省资源、不无意义抓取 |
| 恢复补偿 | 系统恢复后补偿检查，区分"实时触发"与"恢复后发现已触发" | 避免过期通知一次性轰炸 |
| 技术实现 | Windows/Mac 具体机制留到 MVP 开发阶段由用户选型 | 原型阶段只记需求 |
