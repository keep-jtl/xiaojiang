## 1. 目标与需求

### 1.1 一句话目标

小财通只保留**一份**"某市场此刻是交易中/未开盘/已收盘/休市"的判断逻辑（纯函数 + 本地日历库），首页、盯盘提醒及以后所有页面统一调用；判断依据为**各交易所实际开市日日历**，离线可用、联网自动更新、失败降级不猜。

### 1.2 已确认需求（用户 2026-09-05 拍板，8 条）

1. A股、港股、美股**三个市场分别判断**交易日（三市场节假日不同）
2. 交易日历**本地缓存**（SQLite），离线也能判断四态：交易中 / 未开盘 / 已收盘 / 休市
3. **首次内置当年+下一年基础日历**（2026、2027），无网也不把春节/国庆/圣诞等休市日误判成交易中
4. 联网时**定期自动更新**后续年份日历，不需要用户手动更新代码
5. 更新失败时**继续用本地已有日历**，不允许退化成"工作日就算交易日"
6. 美股正确处理**夏令时/冬令时**（美东 EDT/EST，2026 年 3 月第二个周日 8 日生效 ~ 11 月第一个周日 1 日结束），不能全年固定同一北京时间时段
7. 界面只显示小白能懂的四态（交易中/未开盘/已收盘/休市）；内部可复杂、界面不复杂
8. **统一底层服务**，首页、盯盘提醒以后复用同一套判断逻辑——只允许一份时段判断实现

### 1.3 与既有文档的一致性检查

## 3. SQLite 存储设计

### 3.1 建表 SQL（拟作为第 11 张表，归属"数据源缓存（可重建）"类）

沿用 schema v2 conventions：日期 TEXT `YYYY-MM-DD`、整数标记、source 留痕、中文行内注释。字段名用 `market`（与 `market_meta.market` 的 cn/hk/us 口径一致），不用 `code`（避免与行情代码混淆）。

```sql
-- 11. 交易日历（三市场统一；日历缺失≠休市：查不到必须显式报错，绝不按"工作日"猜）
CREATE TABLE IF NOT EXISTS market_calendar (
    market      TEXT NOT NULL,             -- 市场代码：cn=A股 / hk=港股 / us=美股
    trade_date  TEXT NOT NULL,             -- 该市场本地日期 YYYY-MM-DD（美股=美东日期，勿用北京日期）
    is_open     INTEGER NOT NULL CHECK (is_open IN (0,1)),
                                           -- 1=交易日 0=休市日（存全量：休市日也入库；
                                           -- 查不到行=日历缺失，触发显式报错而非当休市）
    early_close TEXT,                      -- 提前收盘时刻 HH:MM（本地口径）：
                                           -- 港股半天交易日='12:00'（除夕/圣诞前夕/新年前夕）；
                                           -- 美股黑五='13:00'（美东口径）；NULL=正常收盘
    source      TEXT NOT NULL,             -- 数据来源：builtin/sina/ics1823/rule_xnys/manual
    fetched_at  TEXT NOT NULL,             -- 写入时刻（本地时间 'YYYY-MM-DD HH:MM:SS'）
    PRIMARY KEY (market, trade_date)
);
CREATE INDEX IF NOT EXISTS ix_market_calendar_market ON market_calendar(market, trade_date);
```

**设计要点**：

1. **存全量（含休市日）而非只存交易日**：只存交易日时，"查不到"无法区分"休市"与"日历缺失"。存全量后，查不到=日历缺口，必须报错（需求 5 的防线）。
2. **美股 trade_date = 美东日期**：美股交易时段横跨北京午夜（北京时间 21:30 ~ 次日 4:00），若用北京日期存，北京凌晨 2:00 应算"昨晚的美股交易日"还是"今天的"会纠缠不清。统一约定：美股行按美东当地日期存，引擎先把北京时刻换算成美东时刻再查表（见 §4.3）。
3. **early_close 一列解决半天交易日**：港股除夕/圣诞前夕/新年前夕 12:00 收盘（港交所通告确认：2026 为 2/16、12/24、12/31；2027 为 2/5、12/24、12/31）；美股黑五 13:00 美东收盘（2026-11-27、2027-11-26）。界面四态不受影响，仅"已收盘"时刻提前。
4. 建表验证已于 2026-09-05 在临时库完成（CHECK 约束生效、UPSERT 可用），临时库已删除；验收库 data/xltc.db **未做任何改动**。

## 4. 时段引擎设计（纯函数、无副作用、易单测）

### 4.1 四态定义（界面口径）+ 内部五态（引擎口径）

| 界面四态（需求 7，小白可见） | 内部状态值 | 含义 |
|---|---|---|
| 交易中 | `trading` | 该市场本地日期是交易日，且当前时刻在交易时段内 |
| 未开盘 | `preopen` | 交易日，但还没到开盘时刻 |
| 已收盘 | `closed` | 交易日，且已过收盘时刻（含半天交易日提前收盘） |
| 休市 | `holiday` | 该市场本地日期不是交易日（周末/节假日/临时休市） |
| 休市（同左） | `noon_break` | **内部多出的第五态**：交易日午间休市（A股 11:30-13:00、港股 12:00-13:00），界面并入"休市"（见下） |
| （错误态，非常规四态） | `no_data` | 日历缺失，无法判断——必须显式报错，绝不猜 |

**午休映射建议**（需求 C 要求给出建议和理由）：交易日中午（A股 11:30-13:00、港股 12:00-13:00）界面显示**「休市」+ 小字说明"午间休市 · 13:00 开盘"**。

- 理由 1（字面准确）：中午市场确实处于休市状态，标"休市"字面最准；若标"未开盘"，小白会误以为"今天还没开过市"，与事实（上午已交易过）矛盾。
- 理由 2（消除歧义）：全天休市（节假日）和午间休市都叫"休市"可能混淆，因此用小字 note 区分——午休时 note="午间休市 · 13:00 开盘"，节假日时 note="今日休市"，一眼可辨。
- 理由 3（内部可复杂、界面不复杂）：需求 7 明确允许内部更细。引擎内部保留 `noon_break` 五态，将来盯盘提醒要用（午休不检查行情），界面始终只显示四个词。

美股盘前/盘后（美东 4:00-9:30 / 16:00-20:00）按需求 6 处理：盘前归"未开盘"、盘后归"已收盘"，界面无第五种状态。

### 4.2 引擎函数签名与输出

```python
# app/market_cal.py
def session(market, now_bj, is_open, early_close=None) -> (state, open_at, close_at)
#   market: 'cn' | 'hk' | 'us'
#   now_bj: datetime（本地时间，即北京时间；引擎不依赖系统时区设置，默认约定北京）
#   is_open: 查表结果（该市场本地日期是否交易日；查不到由调用方先判 no_data）
#   early_close: 表中 early_close（'HH:MM' 或 None）
#   返回: state 五值之一；open_at/close_at 为该市场本地口径的 'HH:MM'（us 为美东口径）
```

时段常量（集中在引擎一处，全项目唯一）：

| 市场 | 开盘 | 午休 | 下午开盘 | 收盘（正常） | 备注 |
|---|---|---|---|---|---|
| cn | 09:30 | 11:30-13:00 | 13:00 | 15:00 | 北京时间 |
| hk | 09:30 | 12:00-13:00 | 13:00 | 16:10 | 北京时间；16:00-16:10 收市竞价视为交易中 |
| us | 09:30 | 无 | — | 16:00 | **美东时间**；半天日（黑五）13:00 |

判断流程（纯函数，21 条断言已于 2026-09-05 全部实测通过）：

```
若 market in (cn, hk)：用北京时间日期 D + 时刻 t
若 market == us：先换算美东时刻（见 4.3），得美东日期 D + 时刻 t
查表 (market, D)：查不到 → no_data；is_open=0 → holiday
early_close 有值且 ≤ 午休开始时刻 → 该日无午休（半天交易日）
t < 开盘 → preopen
开盘 ≤ t < 午休开始 → trading
午休开始 ≤ t < 午休结束 → noon_break
午休结束 ≤ t < 收盘 → trading
t ≥ 收盘 → closed
```

### 4.3 美股夏令时/冬令时处理（需求 6，核心正确性）

**规则（自实现，不依赖 zoneinfo/tzdata，离线可用）**：

- 3 月第二个周日（含）~ 11 月第一个周日（不含）为 EDT（美东夏令时，北京差 12 小时）
- 其余为 EST（美东冬令时，北京差 13 小时）
- 2026：EDT = 2026-03-08 ~ 2026-11-01；2027：EDT = 2027-03-14 ~ 2027-11-07

**北京时间 → 美东时间"两步修正法"**（切换发生在美东凌晨 2:00，远离 9:30/16:00，分钟级边界不影响开收盘判断）：

```python
def ny_from_beijing(now_bj):
    off1 = -12h if 美东日期(now_bj.date()) 属 EDT else -13h   # 按北京日期先猜
    ny = now_bj + off1
    off2 = -12h if 美东日期(ny.date()) 属 EDT else -13h       # 按美东日期校正
    return now_bj + off2 if off1 != off2 else ny
```

**已实测验证**：自实现规则与 Python 标准库 zoneinfo("America/New_York") 在 3 个边界时刻（2026-03-09 21:30、2026-11-02 21:30、2026-11-02 05:00）**换算结果完全一致**（2026-09-05 实测）。

## 6. 更新机制（需求 4/5）

### 6.1 统一入口：`ensure_calendar(conn, markets=("cn", "hk", "us")) -> dict`

幂等单函数，可重复调用：

```
1. 库内 market_calendar 无该市场数据 → 导入内置 2026/2027（builtin），全部展开为全量行
2. 检查该市场库内最大 trade_date：
   - 不足"当前年份 + 1 年" → 需要补充次年：
     · cn：联网拉新浪（若源提供的最新日期 > 库内最大日期，UPSERT 新行）
     · hk：联网拉 1823 ICS（解析后 UPSERT）
     · us：本地规则生成次年（假日规则固定，不需要联网）
   - 已足 → 跳过（幂等）
3. 每天最多联网尝试一次：app_meta.calendar_check_date 占位（2026-09-04 决策；原与净值
   auto_refresh_date 同款机制，**2026-09-25 起净值已改按基金逐只时段状态判断
   （app_meta.nav_refresh_state），本日历机制不变**）；失败静默：旧数据原样保留，次日再试
4. 返回 {"ok": true, "imported": bool, "fetched": {...}, "detail": "..."}（幂等）
```

**降级红线（需求 5）**：联网失败绝不触发"按工作日推算"——库内旧日历继续生效；只有"查不到某市场某天"才暴露为 `no_data` 并显式报错。

### 6.2 调用点

- `main.py` 启动时后台线程调用一次（不阻塞窗口）；
  - **2026-09-25 更新**：已收敛到统一后台刷新器 `app/refresher.py`：每个 tick（启动立即一次、之后每 600 秒一次）调用一次，`main.py` 不再单独起线程；因为是幂等的、且自带「每市场每天最多联网一次」防抖，频繁调用是安全的；
- `api.get_market_sessions()` 内兜底触发（不等待结果，直接用库内现状计算）。

### 7.2 `api.get_market_sessions()` 契约（首页 JS 调用）

```python
def get_market_sessions(self):
    """三市场当前四态 + 排序建议 + 展示文案（统一时段服务唯一入口）
    返回：
    {
      "ok": true,
      "checked_at": "2026-09-07 10:30:05",
      "markets": {
        "cn": {"state": "trading",        # trading/preopen/closed/holiday/no_data
                                              #（noon_break 在 API 层已并入 holiday，界面只见四态）
               "label": "交易中",          # 最终展示词（四词之一）
               "note": "今日 15:00 收盘",  # 数据含义说明（已收盘→"数据截至15:00"）
               "open_at": "09:30", "close_at": "15:00",
               "trade_date": "2026-09-07", # 判定依据的市场本地日期（us=美东日期）
               "is_open_day": true,
               "calendar_source": "sina"},
        "hk":  {...},
        "us":  {...}
      },
      "order": ["cn", "hk", "us"],        # 推荐展示顺序：交易中在前，其次未开盘/已收盘/休市
      "hero_text": "A股交易中 · 重点看这里",  # 顶部速览文案（沿用原型文案库）
      "missing": [],                      # 日历缺失的市场列表
      "warnings": [{"market": "us", "text": "美股交易日历为内置规则生成，临时休市公告请留意更新"}]
    }"""
```

**错误语义（需求 E）**：某市场日历缺失时，该市场 `state="no_data"`、`label="未知"`、`note="交易日历缺失，无法判断交易状态，请检查网络后重试"`，并加入 `missing` 数组；前端在速览卡顶部显示警示条。**绝不显示"按工作日推算"的任何结果**。

`order` 排序规则：`trading → preopen → closed → holiday`，同状态按 cn→hk→us 固定序；用户在首页手动固定的市场由前端置顶（产品规划 §20.2"用户固定优先"，API 不参与）。`hero_text` 沿用原型文案库（"A股交易中 · 重点看这里"/"美股交易中 · 重点看这里"/"A股已收盘 · 看收盘表现和基金净值"/"周末全球休市 · 看看周五收盘"等），按 order[0] 对应文案生成。

### 7.3 文案生成规则（集中 API 层，前端零拼装）

| state | label | note（示例） |
|---|---|---|
| trading | 交易中 | 今日 15:00 收盘（半天日自然显示 12:00/13:00） |
| holiday（午休） | 休市 | 午间休市 · 13:00 开盘 |
| holiday（非交易日） | 休市 | 今日休市（美股若北京时间今晚开盘，note="今晚 21:30 开盘"） |
| preopen | 未开盘 | 09:30 开盘（us 显示"北京时间 21:30 开盘"） |
| closed | 已收盘 | 数据截至 15:00（us：数据截至美东 16:00） |
| no_data | 未知 | 交易日历缺失，无法判断交易状态，请检查网络后重试 |

### 7.4 前端改造契约（首页改造时照做，本设计不写前端代码）

1. 删除 `market.js` 的时段模拟器（原型痕迹，与 2026-09-04"清理原型演示入口"方向一致）；
2. 页面加载后按 2026-09-04 通用规则（按钮绑定不依赖 js_api、取数前轮询等待 js_api 就绪 100ms×10s）调用 `get_market_sessions()`；
3. 每行 `.mkt-row` 按 `markets[].label/note` 设置 `.mkt-status` 徽标（四词）与说明文案；`note` 放行内 small 位置；
4. 按 `order` 重排市场行（用户固定置顶优先，不冲突）；`primary` 放大样式给 `order[0]` 对应市场；
5. `hero_text` 替换顶部 `#sessionHero`；基金净值联动行沿用原型逻辑：cn 为 trading/午休时显示"净值更新中（20:00 后更新）"、cn 为 closed 时显示"净值已更新"；

## 9. 风险与待用户确认点

### 9.1 风险（诚实说明）

| 风险 | 影响 | 应对 |
|---|---|---|
| **A股 2027 日历是"预生成"**：2027 年官方休市安排（国务院办公厅 + 交易所公告）要到 2026 年 11~12 月才公布，新浪源现在也只到 2026-12-31 | 2026 年 11 月前，A股 2027 的休市日可能有 1~2 天误差（调休日期未定） | 官方公布后联网更新自动校正；在日历来源界面可标注"2027 为预生成" |
| **美股临时休市日不可预知**：国葬、重大事件等由 NYSE 临期宣布 | 内置日历可能漏掉某天 | 表结构 + ensure_calendar 支持"补丁"机制（追加临时关闭日）；每年 1 月对照 NYSE 官方公布表人工核对一次 |
| 新浪改格式/1823 站点不可达 | 自动更新失败 | 内置表兜底，绝不退化"工作日即交易日"；失败静默次日重试 |
| 港交所官网日历页改版（2026-09-05 实测 404） | 官方网页核对路径变化 | 以通告 PDF/检索 + 1823 ICS 为核对口径 |
| 交易所临时调整（如港股台风/黑雨休市、A股延长休市） | 当日判断可能滞后 | 第一版接受（原型阶段明确过的边界），补丁机制预留；半天/临调公告类调整由 ensure_calendar 增量修正 |

### 9.2 待用户确认点（小白话）

1. **2027 年 A股日历先"预生成"可以吗？** 官方安排要 2026 年 11~12 月才公布，现在没法拿到准确的 2027 休市日。方案：按往年惯例先内置一份"预生成"日历（可能差 1~2 天），官方公布后软件联网自动校正。备选：只内置到 2026 年底，2027 年 1 月前必须更新（更保守但 1 月起可能误判）。推荐：预生成 + 自动校正。
2. **同意新增第 11 张表 market_calendar 吗？** 这是本项目数据库的第 11 张表，存放三市场日历（含休市日），属"数据源缓存"类，可以随时删掉重建、不涉及用户数据。
3. **午休显示方式**：交易日中午（A股 11:30-13:00）界面显示「休市」+ 小字"午间休市 · 13:00 开盘"——请确认这个显示方式是否合意（理由见 §4.1）。
4. **港股半天交易日**：除夕、圣诞前夕、新年前夕港股只开上午（12:00 收盘），界面在这些日子中午后显示"已收盘"（数据截至 12:00）——确认接受。
5. **美股休市提示**：美股休市的白天，如果今晚会开盘，note 会提示"今晚 21:30 开盘（北京时间）"这类文案——确认接受这种提示方式。
6. **exchange_calendars 第三方库**：实测用它做交叉验证很好用，但正式实现**不依赖它**（自写规则已足够且离线可用）。是否同意此取舍？推荐同意。
